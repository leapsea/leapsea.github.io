�入口时，可以让 NAS 主动连接公网服务器，再从外部电脑通过这条连接进入 NAS。本文先建立远程维护通道，后续部署服务时再按需要扩展。

前置条件

需要一台公网 Linux 服务器，以及允许 TCP 转发的 SSH 账户。下面的 tunnel@vps.example.com 是示例账户和服务器地址；NAS 与外部电脑都要能通过 SSH 登录它。

隧道账户建议独立创建，只授予必要的转发权限。连接前核对服务器指纹，设置 SSH 密钥登录；私钥保留在对应客户端。

NAS 建立反向连接

在 NAS 上执行：

ssh -NT \
  -o ExitOnForwardFailure=yes \
  -o ServerAliveInterval=30 \
  -o ServerAliveCountMax=3 \
  -R 127.0.0.1:22022:127.0.0.1:22 \
  tunnel@vps.example.com

公网服务器的 127.0.0.1:22022 会转发到 NAS 的 SSH 端口。它只监听服务器本机，无需设置 GatewayPorts yes，也不需要在公网放行 22022。保持这个终端运行。

参数行为可以查阅 OpenSSH 官方手册 。ExitOnForwardFailure 用来发现监听建立失败，不能证明目标服务一直可用；保活参数也不会自动重连。

外部电脑连接 NAS

在外部电脑开启第二段隧道：

ssh -NT \
  -o ExitOnForwardFailure=yes \
  -L 127.0.0.1:2222:127.0.0.1:22022 \
  tunnel@vps.example.com

再开一个终端，使用 NAS 上的账户登录：

ssh -p 2222 your-nas-user@127.0.0.1

两段隧道都需要保持连接。连接 NAS 时核对的指纹应是 NAS 的主机指纹。

验证后再保活

确认断开隧道后连接失效、重新建立后连接恢复，再考虑用 systemd 管理 NAS 端 SSH 进程。服务需使用独立账户、已核对的 known_hosts 和可用于无人值守的专用密钥，配置 BatchMode=yes、Restart=always 与重试间隔；不要靠关闭主机指纹检查解决启动失败。

公网服务器的带宽、家庭上行带宽和往返延迟都会影响体验。这个示例提供 SSH 入口，不会自动开放可道云或 GitLab；后续 Web 服务需要增加相应转发，并核对服务的访问地址。多人长期访问时，可以另行评估私有组网或带 HTTPS 的访问入口。 ���������������������������������
