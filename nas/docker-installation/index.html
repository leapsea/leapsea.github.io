家庭NAS环境搭建（二）：Docker安装

2026年10月06日 ·1 分钟阅读 ·折腾

目录

  • 安装范围
  • 配置软件源
  • 验证安装
  • 数据与权限

系统与访问入口准备好后，接下来安装 Docker。后续的可道云和 GitLab 都使用 Compose 配置，让端口和持久化目录可以随配置一起维护。

安装范围

以下步骤适用于全新的 Debian 13 主机，依据 Docker 官方 Debian 安装文档 。已有 Docker、Podman 或 containerd 的机器，先按官方文档检查冲突包和现有工作负载，不要直接卸载覆盖。

配置软件源

sudo apt update
sudo apt install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/debian/gpg \
  -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

添加对应系统代号和架构的软件源：

sudo tee /etc/apt/sources.list.d/docker.sources > /dev/null <<EOF
Types: deb
URIs: https://download.docker.com/linux/debian
Suites: $(. /etc/os-release && echo "$VERSION_CODENAME")
Components: stable
Architectures: $(dpkg --print-architecture)
Signed-By: /etc/apt/keyrings/docker.asc
EOF

sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io \
  docker-buildx-plugin docker-compose-plugin
sudo systemctl enable --now docker

验证安装

sudo docker version
sudo docker compose version
sudo docker run --rm hello-world

确认服务端可以响应，Compose 插件可用，测试容器能正常退出。后续使用的是 docker compose 命令。

数据与权限

sudo mkdir -p /srv/compose/kodbox /srv/compose/gitlab
sudo mkdir -p /srv/appdata/kodbox /srv/appdata/gitlab

这些目录沿用第一篇的约定，创建前确认数据盘挂载正确。本系列用 sudo docker 执行管理操作；加入 docker 用户组会获得很高的主机权限，按需决定。

应用通过挂载目录保留数据。以后重建容器前，先检查挂载配置；清理未使用卷时也要确认它不是某个停用服务的数据。

发布端口应绑定到实际需要的地址。Docker 发布端口与主机防火墙的交互需要单独检查，不能仅凭 ufw 规则推断服务未对外开放。
