家庭NAS环境搭建（一）：系统选型

2026年10月06日 ·2 分钟阅读 ·折腾

目录

搭 NAS 之前，先想清楚它要做什么。这个合集的目标是文件管理、远程访问和自托管 Git 服务，后续应用统一用 Docker 管理，因此采用通用 Linux 作为示例底座。

选择 Debian 作为示例系统

本系列使用 Debian 13。它提供系统基础环境，应用通过后续的 Compose 配置管理。安装介质与版本状态可以查看 Debian 官方发行页面 。

这是本教程的工程选择：适合愿意使用 SSH、配置文件和命令行维护的读者。如果主要需求是图形化管理共享、磁盘池和快照，可以先评估专用 NAS 系统；这些系统的磁盘管理和应用安装方式需要按各自文档操作，不能直接照搬本文后续命令。

先规划资源和磁盘

不要仅按文件共享的需求购买硬件。GitLab 包含数据库和后台任务，资源预算应以第五篇链接的官方要求为依据；给系统与可道云留出额外余量。

建议把目录职责分开：

/srv/
├── compose/          # 各服务的部署配置
│   ├── kodbox/
│   └── gitlab/
├── appdata/          # 数据库、应用配置和持久化文件
│   ├── kodbox/
│   └── gitlab/
└── storage/          # 后续规划的共享文件目录

目录只是约定，创建目录不会自动把数据写入数据盘。先确认目标磁盘已经挂载，再建立应用数据目录；否则大文件可能写满系统盘。

lsblk -f
findmnt /srv
df -h /srv

这里不提供格式化磁盘的快捷命令。已有数据的磁盘要先确认文件系统和备份，再决定如何接入。

安装后的基础检查

安装时创建普通管理员账户，确保可以使用 sudo。需要远程维护时安装 SSH 服务：

sudo apt update
sudo apt install -y openssh-server ca-certificates curl git
sudo systemctl enable --now ssh
hostnamectl
ip -br addr
free -h

在路由器里为 NAS 保留固定的 DHCP 地址，以下教程统一用 192.168.1.100 举例。从另一台内网电脑测试：

ssh your-user@192.168.1.100

备份先于部署

应用数据、部署配置和个人文件都需要备份。至少保留一份不依赖这台 NAS 的副本，并尝试恢复一个测试文件。等内网 SSH 登录和磁盘挂载都确认正常，再继续配置远程访问。
